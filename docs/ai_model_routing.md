# モデルルーティング / トークン ROI 方針

> CLAUDE.md「モデルルーティング / トークン ROI」セクションの詳細版。
> メインセッションが Fable5 のときに、出力品質を下げずにトークン消費を抑えるための運用ルール。

## 基本思想

Fable5 は「全部を実行するモデル」ではない。**設計・判断・監査・レビュー・最終品質担保**に集中させ、
中間作業は Opus/Sonnet のサブエージェントに委譲する。節約する対象は**中間作業のみ**で、
最終成果物の品質は絶対に下げない。Fable5 の節約そのものを目的化しない — 勝負所に集中させるための手段。

## Fable5 が直接扱う（委譲しない）

- 設計判断・アーキテクチャ選定（間違えると手戻りが大きい箇所）
- UX・事業・プロダクトに影響する判断
- 実装難易度が高い箇所、非自明なトレードオフを含む箇所
- 複数の変更を束ねる整合性の確認、フェーズ統合のような横断設計
- 最終レビュー・セキュリティ判断・マージ可否の最終確認

## サブエージェントに委譲する（中間作業）

| 作業 | 委譲先の目安 | エージェント例 |
|---|---|---|
| 調査・コード読解・横断検索 | Sonnet/Opus | Explore, general-purpose |
| 既存実装の構造把握 | Sonnet | code-explorer 等 |
| 単純実装・定型実装 | Sonnet | general-purpose |
| テスト追加 | Sonnet | tdd-guide |
| 差分確認・レビュー一次パス | Opus/Sonnet | code-reviewer, security-reviewer |
| 軽微な修正・整形 | Sonnet/Haiku | general-purpose |

> モデル指定はサブエージェント定義の frontmatter / Agent 呼び出しの `model` で行う。
> 迷うときは Sonnet を既定にし、深い読解・レビューが要る場合のみ Opus。

## 委譲のしかた（最小コンテキスト）

- サブエージェントには**必要最小限のコンテキスト**だけ渡す。会話全文や無関係なファイルを渡さない。
- 「どこを見るか」は [context_index.md](context_index.md) を使って絞る。
- 1 サブエージェント = 1 明確なタスク。スコープを広げない。
- プロンプト雛形は [subagent_prompt_templates.md](subagent_prompt_templates.md) を使う。

## 返却フォーマット（圧縮）

サブエージェントには、生のファイルダンプではなく以下に**圧縮して**返させる:

1. **変更内容** — 何をどう変えた / 何が分かった（事実）
2. **判断理由** — なぜそうしたか
3. **懸念点** — リスク・未解決・前提
4. **Fable5 が判断すべきこと** — 設計整合性・UX・実装リスクで人/Fable5 の確認が要る点

## 最終ゲート（必ず Fable5）

委譲結果は鵜呑みにせず、Fable5 が最終的に確認する:
- 設計整合性 / UX / 実装リスク / 品質
- 受け入れ条件との突合
- [quality_checklist.md](quality_checklist.md) の通過

## アンチパターン

- Fable5 で巨大ファイルを通読する（→ Explore に投げて結論だけ受け取る）
- サブエージェントに会話全文を渡す（→ 最小コンテキスト）
- 委譲結果を未検証でそのまま採用する（→ 最終ゲートを飛ばさない）
- 品質に直結する設計判断・最終レビューを委譲する（→ Fable5 が担保）
- 節約のために必要な確認を省く（→ 中間作業のみ節約）
