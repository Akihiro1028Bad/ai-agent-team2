### 4. ワークフローセクション

現行テーブルを維持しつつ、各フローを Mermaid ライクなステップ表記で補強。
`dispatcher.py` と `type_detection.py` が担うタイプ判定フローを簡単に図示。

**タイプ別フロー表（更新）**

| タイプ | 自動判定 | フェーズ | コスト目安 |
|-------|---------|---------|-----------|
| 🐛 Bug | エラー・不具合 | `ANALYSIS` → 👍承認 → `FIX` → PR | ~$0.80 |
| ⚡ Feature-S | 1〜3ファイル変更 | `HEARING` → `PLAN_BRIEF` → 👍承認 → `IMPLEMENT` → PR | ~$0.90 |
| 🏗️ Feature-M | 複数ファイル・設計必要 | `HEARING` → 設計PR → approve → `PLANNING` → `IMPLEMENT` → PR | ~$1.50 |
| 🏢 Feature-L | 大規模・分割必要 | `HEARING` → 分割提案 → 子Issue作成 → 各子をタイプ別処理 | $2.0 + N×$1.50 |

## 実装上の注意点

### ASCII アート・バナー

- タイトル部は `figlet` 風のテキストアートで装飾する（例: `╔══╗` の罫線ブロック）
- GitHub の Markdown レンダリングで崩れないよう ```` ```  ```` ブロック内に配置する

### バッジ

- shields.io の動的バッジ（CI, Issues）と静的バッジ（Python, uv, ruff）を組み合わせる
- バッジが増えすぎないよう1行7個以内に収める

### 絵文字

- セクション見出しとリスト項目に絵文字を添える
- 本文の流れを妨げない範囲で使用し、過剰添付しない

### 情報の正確性

- `phases/` に追加された `type_detection.py`, `dispatcher.py`, `split.py`, `impl_revise.py`, `design_revise.py` を「プロジェクト構成」ツリーに追記する
- バージョン番号等は `pyproject.toml` の値に準拠する
