# サブエージェント・プロンプト雛形

> 中間作業を Opus/Sonnet に委譲するときの定型プロンプト。詳細方針は [ai_model_routing.md](ai_model_routing.md)。
> いずれも末尾に「圧縮返却」を必須化し、Fable5 が判断すべき点を明示させる。

## 共通の返却指定（全テンプレ末尾に付ける）

```
返却は以下に圧縮すること（生のファイルダンプ禁止）:
1. 変更内容/判明事実  2. 判断理由  3. 懸念点  4. Fable5 が判断すべきこと
```

## 1. 調査・コード読解（Explore / general-purpose）

```
目的: <知りたいこと> を特定する。
対象: <ディレクトリ/機能の範囲>。
やること: 関連ファイルを読み、<具体的な問い> に答える。実装は変更しない。
出力: ファイル:行 付きの結論のみ（全文ダンプ不要）。
<共通の返却指定>
```

## 2. 単純実装（general-purpose / Sonnet）

```
背景: <最小限の前提（CLAUDE.md 規約は遵守）>。
タスク: <変更内容を一意に>。対象ファイル: <パス>。
制約: 既存パターンに合わせる / mypy strict・ruff 通過 / 無関係な変更をしない。
完了条件: <受け入れ条件>。
<共通の返却指定>
```

## 3. テスト追加（tdd-guide）

```
対象: <テストする関数/挙動>（<ファイル:行>）。
方針: TDD。境界値・異常系を含める。既存の fixture/Fake を使う。
完了条件: pytest 通過、対象の主要分岐をカバー。
<共通の返却指定>
```

## 4. 差分確認・レビュー一次パス（code-reviewer / security-reviewer）

```
対象: `git diff <base>...HEAD`（または <パス>）。
観点: <correctness / security / 規約整合 / テスト抜け など>。
各指摘に severity（CRITICAL/HIGH/MEDIUM/LOW）とファイル:行。問題なしの観点も明記。
実コードを読んで検証すること。
<共通の返却指定>
```

## 5. 軽微な修正・整形（Sonnet/Haiku）

```
タスク: <型修正/lint 修正/小さな整形> を最小差分で。
制約: 挙動を変えない。無関係な箇所を触らない。
完了条件: <ゲート> が通る。
<共通の返却指定>
```

## スコープ管理

- 1 サブエージェント = 1 タスク。広がりそうなら分割して並列化。
- 渡すコンテキストは最小限（会話全文・無関係ファイルを渡さない）。
- 独立タスクは 1 メッセージで並列起動する。
